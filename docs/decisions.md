# Decisions

Dated, with the reason. Newest at the bottom. The spec in `spec.md` states the result; this file says why.

## 2026-10-22, the day the spec was settled

- **Meetings only, no dictation.** Dictation needs sub-second local models and OS-level text insertion, a different product with different constraints. Wispr Flow, TypeWhisper and Monologue exist for it.
- **Own build, not Speakr.** Speakr (AGPL-3.0) has most of the server features, but its surface is a homelab tool: a 0.x alpha, a dense UI, one maintainer. An IT department reads that as vendor risk. The enterprise layer, a calm UI, an admin surface IT can sign off, a version 1.0 with a company behind it, is the product.
- **Not TypeWhisper as the foundation.** A personal dictation app, GPL-3.0, one user per machine, no server. Worth taking: knowledge of local engines and the keyterm idea. Not code.
- **Licence: PolyForm Noncommercial 1.0.0**, the same as scene-loop. Changed from MIT the same day. Free to read, run and change for noncommercial use; a company running it in its business licenses it from Primux, which is the business model. Source-available rather than open source. Dependencies stay permissive (MIT, Apache-2.0, BSD, ISC); no GPL, AGPL or MPL copied in.
- **Docker, installs anywhere.** The first installs are a Microsoft house with Azure and a Dropbox house with no Azure. Not Azure-only.
- **Desktop recorder is capture route 1.** Pulling Teams or Meet recordings only works for meetings the company organised. A participant in someone else's meeting gets nothing. The recorder is our own Tauri 2 and Rust app. Vibe (MIT, about 27k lines of Rust), anarlog (MIT core, about 318k lines) and Meetily (MIT) are references for system audio capture and local models, not code we copy; the licence of this repo is not MIT, and a clean codebase is easier to license commercially than a fork. Changed from "fork Vibe" the same day.
- **Library stack: Laravel and Livewire.** The author's fastest stack. Queues plus provider adapters are the whole backend. Superseded the same evening, below.
- **Public repo from day one.** Licence and history clean from the first commit. No announcement before the second install runs.
- **Local models download from Hugging Face directly.** Zero work; revisit if an install's network blocks it.
- **Audio is sent after the meeting, chunked and resumable.** A 2-hour meeting is 100 MB or more on hotel wifi. The live transcript is local, so nothing needs the server during the meeting.
- **The laptop keeps its copy for 7 days after a confirmed upload.** The author lost recordings to a notetaker that deleted after a failed upload, more than once. Confirm means whole file plus hash match.
- **Warn after 24 hours without a confirm, keep retrying 7 days.** Covers a weekend offline.
- **Several recordings per meeting, one primary.** A voice recorder plus a laptop, or two colleagues recording, is the common case.
- **Speakers are free labels that can link to a directory user.** The same colleague is the same person across meetings; externals stay plain labels.
- **An admin never reads a private meeting.** Metadata and audit only. Private means private; retention still deletes it.
- **Only the owner changes visibility.** Shared colleagues read, they do not re-share.
- **Retention is per install with a keep flag per meeting.** Board minutes stay, the weekly standup goes.
- **Several recap templates per install, admin edits, user picks.** Board minutes, team decisions and an interview summary are three shapes at one small organisation alone.
- **The recap is an editable document inside the platform.** Notion-style Tiptap editor, rebuilt on Tiptap core and open extensions from a design the author already shipped elsewhere. Tiptap's own Notion-like template needs a paid plan in production and a Pro licence, so it cannot be redistributed in this repo.
- **MCP per user only, OAuth with the company login.** No service identity in v1. Read tools plus write tools (save minutes, set visibility, share), each write an audit row.
- **Live transcript in a small floating window, always on top, preview only.** One transcript per recording, made with keyterms and diarization on the server. No two versions to reconcile.
- **Browser recorder and file upload in v0.1, phone app later.** A browser recorder is a week; a phone app is a quarter.
- **Name: mtxt.** "Meeting text." The product name employees see is a setting per install.
- **First install's provider: AssemblyAI EU endpoint with their DPA.** ElevenLabs Scribe was the first choice for Danish quality, but on a self-serve plan EU residency and zero retention are Enterprise-only, and audio sits in US request history. A local model is tested alongside on the same recording.
- **Repo: primux-dk/mtxt.** Primux is the company the About page names.
- **One repo for recorder and library**, laid out like anarlog: `apps/server`, `apps/recorder`, `packages/contract`. The upload contract is the seam, and one repo lets a contract change land in both halves in one commit. A separate recorder repo was the earlier plan and is dropped.

## 2026-10-22, evening: the stack and who runs it

- **Next.js and shadcn/ui on Cloudflare Workers, not Laravel.** The product should be sellable, and Cloudflare's primitives fit it: R2 for audio with no egress fees, Queues, Durable Objects for resumable uploads, D1, Workers AI with Whisper, AI Gateway in front of the recap model, and a remote MCP server with OAuth from the agents SDK. Tiptap's open React components make the recap editor an assembly job. Storage, queue and database go behind adapters so a Docker edition stays possible; it is not built in v0.1.
- **Every install runs in the owning company's own Cloudflare account.** Primux does not host, not even a VPS per customer. Primux deploys with wrangler and holds no customer data. This is what makes the licence and the sale simple: the customer owns the account, the data and the bill.
- **The author's own install comes first.** Built for Primux's own meetings, used for a while, then offered to customers if it holds up. No customer deadline anchors the build.
- **Speech-to-text providers stay adapters.** AssemblyAI with an EU endpoint, Azure Speech, ElevenLabs Scribe, Workers AI Whisper. The company's own contract decides. ElevenLabs on a self-serve plan processes in the US with retention; EU residency and zero retention there are Enterprise-only, checked 2026-10-22.
- **Domains.** `mtxt.co` is the marketing site, `app.mtxt.co` the author's own install. Customers run on hostnames in their own zones.
- **EU processing is stated, not promised.** R2 and Durable Objects pin data to the EU on any plan; Worker placement and D1 location do not, and Cloudflare's Data Localization Suite is Enterprise-only. The admin's data-flow page says exactly that. Checked 2026-10-22.
- **AI Gateway fronts what it supports.** ElevenLabs, Deepgram, Workers AI and the recap model go through it; AssemblyAI is not a supported provider and is called directly. Checked 2026-10-22.
- **English interface at source, Danish as a translation.** Every string is written in English and translated through locale files; Danish is the first translation and the author's own install runs in Danish. An install outside Denmark gets a first-class interface, and Danish stays one translation among others instead of the source that everything else is derived from. Transcription language is a separate setting and stays Danish first. Kristian's call, 2026-10-22, during the design review; the first mockups were written in Danish and are redone in English.
- **Recap and transcript are tabs on the meeting page**, not two columns. Two columns squeezed the transcript to half the width and gave the recap editor no room; one panel at a time at the full content width reads better on every screen size and is the same layout on a phone. Kristian, 2026-10-22, from the first mockup.
- **Installs may tweak two colours.** Accent and button colour, with everything else derived and contrast enforced. A company that runs the app under its own product name wants it to look like its own, and two values cover that without a theme editor. Design guidelines live in the repo as HTML and are served by the app at `/design` from the live tokens, so the reference and the install never drift apart. Kristian, 2026-10-22.

## 2026-10-22, v0.1 packet 1: the scaffold

- **`meetings.archived_at` joins the data model.** Behaviour rule 3 separates archive (out of the library views, restorable) from delete (permanent). A nullable timestamp is the smallest way to hold it; `deleted_at` stays for the delete path.
- **Every row's `install_id` comes from the Worker variable `INSTALL_ID`.** One install per account, so the value is fixed per deploy, set in `wrangler.jsonc` vars, and written by the seed. Local development uses `dev`.
- **First migration is `0000_init.sql`.** drizzle-kit numbers from 0000 and tracks the names in its journal; renaming it would make the next generated migration collide. Wrangler applies the folder in name order and does not care where numbering starts.
- **The default transcription language seeds as `auto`.** The packet's seed list did not name one, and `auto` works for an install outside Denmark too. An admin sets `da` in settings.
- **Locale keys that are both a string and a prefix move to `.text`.** next-intl reads dots as nesting, so `meeting.keep` and `meeting.keep.label` cannot both be strings. `meeting.keep`, `recorder.mic` and `recorder.system` became `meeting.keep.text`, `recorder.mic.text` and `recorder.system.text` in `apps/web/messages`. The mockups' flat files keep their keys.
- **No locale prefix in URLs.** The interface language follows `Accept-Language` when a translation exists, else the install default, per the spec. A link then opens in the reader's own language, and the library's URL state stays clean.
- **Mona Sans loads through `tokens.css`'s own `@font-face`.** `globals.css` imports `tokens.css`, and the build bundles the font it points to. One file, no second copy, no `next/font` wrapper.
- **`/design` lives at `/design/`.** The guidelines link to `tokens.css`, `mockups/` and `locales/` relatively, so the page is served with a trailing slash; `/design` redirects there. The files are bundled into the Worker at build time, not copied into `public/`, so the signed-in check in packet 2 covers them all.
- **The app applies the install's two theme values on every page,** not only on `/design`, as a `html:root` style from the settings row. The spec says every colour derives from them.
- **Dark mode follows the operating system.** The design's preview switch is a review tool; the app sets `.dark` from `prefers-color-scheme`.
- **TypeScript 5.9, ESLint 9, Next.js 15 on webpack.** `eslint-config-next` 15 declares ESLint 7 to 9, so ESLint 10 is out. TypeScript 7 is the new native compiler; staying on 5.9 keeps Next.js 15's type check and typescript-eslint on the version they are built against. Webpack (Next.js 15's default) gives the `?raw` imports `/design` needs.
- **The package build script is `next build`; the Worker build is `build:cf`.** OpenNext runs the package's own `build` script, so naming the OpenNext command `build` recursed.
- **shadcn/ui on the Radix base, `radix-nova` style, restyled to the tokens.** The CLI installs its components with the `cn` helper package (MIT, from the shadcn project) instead of clsx and tailwind-merge.
- **The e2e test runs on `wrangler dev`,** on the OpenNext build, with local D1, R2, Queues and the Durable Object. The build takes about 1.5 minutes, which CI makes anyway; `next dev` would test a different runtime.
- **Licence check: runtime dependencies only, exceptions by package name.** `pnpm check:licenses` fails on a runtime dependency outside MIT, Apache-2.0, BSD-2/3, ISC, 0BSD, CC0, Unlicense, Python-2.0 and OFL-1.1. `caniuse-lite` (CC-BY-4.0, data) and six BlueOak-1.0.0 packages (glob and its family, build tooling under Next.js and OpenNext) are named in `scripts/license-exceptions.json` for the lead to confirm, rather than widening the allowed list. Dev-only tools outside the list (lightningcss and axe-core under MPL-2.0, sharp's libvips under LGPL-3.0) run as separate programs at build time and are not shipped.
- **`settings.company_name` and `settings.recording_sources` join the data model.** Both were on the settings screen without a column: the company line under the product name and in the login footer, and the list of recording sources. `company_name` is nullable text, empty at seed; `recording_sources` is a JSON array, seeded with desktop, upload and browser.
- **Seven transitive build packages are accepted licence exceptions.** caniuse-lite (CC-BY-4.0) and the glob family (glob, jackspeak, lru-cache, minimatch, minipass, path-scurry, BlueOak-1.0.0) come in under Next and OpenNext. Both licences are permissive; neither ships in the Worker bundle. They are named one by one in `scripts/license-exceptions.json` with a reason, and the gate fails on anything else outside MIT, Apache-2.0, BSD, ISC and the font's OFL. Accepted under Kristian's standing go, 2026-10-22.

## 2026-10-22, v0.1 packet 2: company login and settings

- **Auth.js (next-auth v5) with Entra ID and Google, configured from the settings row.** No credentials provider, no local users. Auth.js is built per request from the settings row, so a change on the settings page applies to the next sign-in without a deploy.
- **Admins are an email list on the settings row (`admin_emails`).** No user management screen exists, the settings page is the whole admin surface, and an install needs a first admin without a console. The first user to sign in on a fresh install (an empty list) becomes admin. `users.is_admin` is set from the list at sign-in and again when an admin saves the list; the admin check on a request reads the list itself, so removing an admin takes effect at once rather than when the 8-hour session ends.
- **Bootstrap from Worker secrets, then the settings page.** A fresh install has no provider and no admin. The deploy sets `OIDC_PROVIDER`, `OIDC_TENANT_ID`, `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET`; the first request that finds no identity provider in the settings row writes them there, the secret sealed. After that the env values are ignored.
- **Provider credentials live in D1, sealed with AES-GCM under `SETTINGS_KEY`.** Supersedes packet 1's "credentials are Worker secrets, not columns": the settings page is the whole admin surface, and a secret only an operator with wrangler can change is not on it. The page never returns a stored secret; it says "Set" or "Not set" and takes a new value.
- **For Google, the tenant id is the Workspace domain, and sign-in checks it.** Google's OIDC answers for every Google account; without the `hd` check any Gmail user could sign in. Entra's tenant-specific issuer does the same job there.
- **JWT sessions, 8 hours, no session table.** `oidc_subject` is the stable id; name and email are refreshed on every sign-in.
- **The e2e test sign-in is gated at build time, not on `NODE_ENV`.** The e2e suite runs on the OpenNext build, and every Next.js build is `NODE_ENV=production`, so a `NODE_ENV !== "production"` check would keep the route out of the very build the tests run on. Instead the route file is `route.e2e.ts`, a route only when `MTXT_E2E_BUILD=1` adds `e2e.ts` to `pageExtensions` (`pnpm build:e2e`); the module it calls throws on import in a production bundle without that flag, so a normal build that reaches it fails, which a unit test proves; and at runtime it answers only with `AUTH_TEST_MODE=1` and only on localhost.
- **A non-admin's 403 on `/settings` comes from the middleware.** Next.js streams the page, and a `forbidden()` thrown inside the layout's boundaries renders the right page with status 200. The middleware reads the admin list and rewrites to the "Admins only" page with status 403; the page keeps its own `forbidden()` check behind it.
- **Sessions end 8 hours after sign-in, not after the last request.** Auth.js re-issues a JWT on every read, which would make the 8 hours a sliding window; the token carries its sign-in time and both the middleware and Auth.js refuse it after 8 hours.
- **The e2e run has its own local state and placeholder secrets.** `.wrangler/e2e`, wiped at the start of each run, and `apps/web/e2e/e2e.vars` passed with `--env-file`, so a run starts from a fresh install (bootstrap, first admin) and never touches the developer's own `.dev.vars` or local data.
- **A new identity or speech-to-text provider needs its own secret.** A stored secret belongs to one provider's app registration; switching provider with the old one kept would fail at the provider, not on the settings page. Switching to Workers AI Whisper or a local model clears the stored key, since they take none.
- **The data-flow panel says how audio reaches the chosen provider.** AssemblyAI and Azure Speech directly, ElevenLabs and Workers AI through AI Gateway, a local model inside the installation, and a line for no provider yet. The design locale's single "receives audio directly" sentence was wrong for half the list.
- **Template names are unique per install, whatever the casing.** A unique index on `(install_id, name)` and a case-insensitive check on the page; employees pick a template by name per meeting, so two with the same name cannot be told apart. The first template becomes the default; deleting a template keeps the meetings and recaps that used it and drops only the link.

## 2026-10-22, packet 2 review fixes

- **Identity is the OIDC subject, not the address.** A second subject that presents an address already on a user row is refused with "Account conflict, contact your admin", and nothing is written; a unique index holds one user row per address. Before, a second subject with an admin's address became admin. A switch of identity provider gives every user a new subject, so it needs the old user rows cleared first; no screen does that in v0.1.
- **Entra is pinned to the tenant's GUID.** `common`, `organizations`, `consumers` and domains are refused at bootstrap and on the settings page, the issuer is built from the GUID, and sign-in requires the token's `tid` to match. The UPN (`preferred_username`) is the address; the `email` claim, which a user can set, is used only when there is no UPN. Supersedes "a GUID or a verified domain".
- **The first-admin claim runs once.** `admin_bootstrap_claimed_at` is set by the claim, or by the first save of the admin list, and the claim is one UPDATE conditional on it being empty. An emptied list is no longer an open door for the next sign-in.
- **Sign-in requests carry only `callbackUrl` and the CSRF token.** Auth.js merges a sign-in request's fields over the provider's authorization parameters, so `client_id`, `redirect_uri`, `hd` and the rest are stripped before the request reaches it.
- **Sealed values are bound to their column.** AES-GCM additional data `mtxt:<context>:v1`; a value copied to another column does not open. Nothing was deployed, so no value needed resealing.
- **The session token is built from an allowlist:** `sub` (our user id), `name`, `email`, `iat`, `exp`, `signedInAt`. Nothing else from the provider, such as a picture, reaches the cookie.
- **Template names collide on a stored key.** `templates.name_key`, the trimmed, NFKC-normalised, case-folded name, with a unique index, replaces the index on the raw name. JavaScript has no full case fold; lower-casing plus the ß and final-sigma folds covers the cases a European install meets.
- **Keyterm text is CSV per RFC 4180.** Quoted fields may span lines; an unterminated quote or a record with three fields is an error naming the record, and nothing is imported.
- **A fresh install is called "Meetings".** The seed's "mtxt install" put mtxt on the login page until an admin renamed it.

## 2026-10-22, packet 2 second review

- **The cookie names a user; the user row authorises.** The middleware and every page and action resolve the token's subject to the current user row and use its email, name and `is_admin`; a cookie whose row is gone counts as signed out. Supersedes "the admin check reads the list itself": the list sets `is_admin` at sign-in and on every save, and the row is what a stale cookie cannot carry. One D1 read per request.
- **On `/settings`, a server action from a non-admin passes the middleware to its own admin check.** Each action refuses a non-admin with a message the form shows; the 403 page in its place left the form waiting with no answer. Pages still get the 403.
- **Migration 0002 closes the first-admin claim on any install that has a user** as well as on any that has an admin address, so an install whose list was emptied before 0002 is not claimable again.
- **Template keys reach the full fold in two steps.** Migration 0002 can only lower-case ASCII and appends the row id to the later of two colliding names so the unique index can be built; `refoldTemplateKeys()` then runs once per Worker isolate, recomputes every key with the app's fold and renames the later of two colliding templates "<name> (2)". It is idempotent and keeps every id.
- **Keyterm records have exactly one or two fields.** `alpha,2,` is refused with its record number, and formatting quotes any field with a quote, a separator or a line break, so a parsed record round-trips.

## 2026-10-22, v0.1 packet 3: capture, library and meeting page

- **The browser recorder uploads while it records, so the contract takes the size and hash at complete.** `POST /recordings` needs `sha256` and `size_bytes` up front, which a recording still in progress does not have. Both are now optional together: a recorder with the whole file sends them at create, the browser recorder sends them in an optional complete body. `chunk_count`, `sha256` and `size_bytes` are nullable in the API until known; the columns stay NOT NULL and hold `''` and `0` meanwhile (see the migration decision below). The desktop recorder keeps the original flow. A chunk smaller than 8 MB is taken as the last one, and complete checks every chunk against the final size.
- **`chunks_received` is a list on GET and on the chunk receipt.** The receipt had a count; a resume needs the numbers, and one name with two types would confuse the recorder. Nothing used the count yet.
- **Error codes are listed in the contract, not as an enum.** `ErrorBody.code` names the v0.1 codes and `ERROR_CODES` exports them; a later code must not break an older recorder's parser. Forbidden (403) joins the upload calls: a caller who may read the meeting but does not own it.
- **Every chunk is its own R2 part.** In-order chunks are hashed as they arrive with `node:crypto` in the Durable Object. A chunk out of order, a chunk sent twice, or an evicted object drops the running hash, and complete streams the finished object through the hash once. Durable Object memory is lost on eviction but storage is not, so the fallback is also the recovery path. The session logic is `UploadSessionCore`, independent of the Durable Object, so a Docker edition can run it in process.
- **Durable Object jurisdiction falls back only in workerd.** `wrangler dev` throws "Jurisdiction restrictions are not implemented in workerd"; that one error falls back to the plain namespace. A deploy never runs outside `eu`.
- **The first confirmed recording becomes primary**, not the first created. A first upload that fails then cannot leave a broken primary.
- **`complete` answers with the recording at confirmation, then queues and moves on.** The response says `confirmed`; a GET right after says `transcribing`. Calling complete again finishes whatever the last call left undone (confirm, primary, queue), so a crash between steps heals on the retry. The recorder treats `confirmed_at` as the confirmation.
- **The audio route is `/api/v1/recordings/{id}/audio`, library-only.** It is not part of the recorder contract and not in `openapi.yaml`; the contract test still lists the four recorder paths.
- **Search uses `meetings.title_folded`.** SQLite's `LIKE` and `lower()` fold ASCII only, so "MØDE" would not find "Produktionsmøde". The app writes the NFKC lower-case title on create and rename.
- **Upload calls check ownership; reads check visibility.** A caller who cannot read a meeting gets 404, as if it did not exist; one who can read but does not own it gets 403 on upload. Admin has no special read access.
- **The library's status filter replaces the scaffold's four pills.** All, Ready, In progress (uploading and transcribing) and Failed, with counts, from the packet's URL state (`status`). "This week", "Private" and "Shared" stay in the locale files for a later packet.
- **`pnpm db:seed` writes three dev users locally; `--demo[=N]` writes the demo library.** Names are invented. Their subjects are the e2e sign-in's (`test|<email>`), so a test that signs in as one lands on the seeded row and its meetings. The demo replaces the dev users' meetings on every run, so the e2e counts hold. Neither runs with `--remote`.
- **Dates and times render in the reader's own zone and the locale's own format.** next-intl formats with the bare locale (`en`, US style), and the Worker runs in UTC. `LocalTime` formats with `locale.intl` (en-GB, da-DK) in the browser's zone after hydration.
- **`@noble/hashes` (MIT) hashes in the browser.** WebCrypto has no incremental digest, and a 2 GB file cannot be hashed in one buffer.
- **The e2e specs run in one worker.** They share one `wrangler dev` and its local database; specs that add meetings run as the seeded colleague so the dev user's library keeps its 30.

## 2026-10-22, packet 3 after the Codex review

- **Migration 0003 only adds** (numbered 0001 before packet 2 merged). A table rebuild on D1 cascades: `PRAGMA foreign_keys=OFF` has no effect inside D1's migration transaction, so `DROP TABLE recordings` deleted every transcript and segment. 0003 adds five columns and backfills them. Making `sha256` and `size_bytes` nullable is the one change that cannot be additive in SQLite, so they stay NOT NULL with `''` and `0` until complete, and the API answers null for those. `pnpm --filter @mtxt/web check:d1-upgrade` populates a local D1 after 0000, applies 0001 to 0003 and fails on a lost row or a wrong backfill.
- **Packet-1 recordings are backfilled, not re-dated.** `content_type` from the file extension, `created_at` from the meeting's start, and `confirmed_at = created_at` for rows past uploading. No new upload event is invented.
- **Titles fold in the app, once per isolate.** SQLite cannot NFKC-fold or lower-case æ, ø and å, so `title_folded` is nullable and `backfillTitleKeys()` fills the null ones at start-up, with the same fold as create and rename.
- **An upload session does one thing at a time.** Every mutation runs on one in-object queue. One chunk body is admitted at a time; a second PUT gets 409 `busy` with `Retry-After: 1` and its body is not read, and a chunk for a confirmed or failed session is refused before reading. That is what keeps the session at one chunk of memory: measured 8,388,608 bytes peak on a 60 MiB upload sent eight PUTs at a time. The client retries `busy` like a network error.
- **`finalizing` is persisted before R2 assembles the file.** A restart after R2 completed the upload but before the confirmation was saved used to ask R2 to complete it again and fail. A session in `finalizing` checks for the object first and only verifies it.
- **The chunk route authorises before it reads.** Owner, status, `Content-Type: application/octet-stream` (else 415) and a declared length over 8 MiB (413) are checked first; then the body stream goes to the session, which stops reading at one byte past the limit.
- **The browser recording lives outside the page.** `lib/recorder-session.ts` keeps the audio, the recording id and the chunks sent across in-app navigation; a link click while audio is unconfirmed opens a confirm dialog, and leaving stops the recording and keeps it for Retry. Browser Back cannot be held up; the recording is still there when the reader returns. A full unload still loses it, behind the `beforeunload` warning.
- **`confirmed_at` is the confirmation, on every retry path.** A GET that shows it is success whatever the status. A failed upload is never resumed: the retained audio becomes a new recording on the same meeting.
- **Install scope is in every query,** child rows and shares included, and the queue consumer drops a job for another install. The demo seed plants rows from a second install that point into the first, and an e2e spec proves none of it is visible or usable.
- **Strict ranges.** A malformed, empty or multiple `Range` is 416 with `Content-Range: bytes */size`; audio carries `Content-Disposition: inline; filename="recording.<ext>"`. `?t=` is a whole number of seconds from 0 to 86,400, else ignored.


## 2026-10-22, packet 3 on top of packet 2, after the second Codex pass

- **The capture migration is 0003**, after packet 2's 0001 and 0002, with a snapshot generated from 0002's. The upgrade check fills a packet-1 database (a meeting, a transcript, a speaker, three segments, one recording per audio extension) and applies 0001, 0002 and 0003 on top.
- **Every packet-1 audio extension gets its own type**: webm, mp4, m4a, mp3, wav, ogg, oga, opus, flac and aac; anything else becomes audio/webm.
- **The routes and actions use packet 2's session.** `getSessionUser()` in `lib/auth/session.ts`; the stub is gone. The library's test hook (`?state=failed`) needs an e2e build, AUTH_TEST_MODE and localhost, the same three locks as the test sign-in. The middleware's 401 for `/api/v1/` paths is in the contract's error shape, so the recorder gets one shape for every error.
- **Delete is explicit and scoped, and refused across installs.** The schema's foreign keys are one column, so a cascade from a meeting would also delete another install's rows that point at it. Delete now removes each table under the meeting by name and by install, children first, in one transaction. If any row under the meeting carries another install id, delete and archive are refused and nothing changes. The library has no action that removes a single recording, so that rule has nothing to apply to yet.
- **The unload warning lives in the app layout.** It reads the recorder store, so after an in-app Leave every page still asks before a reload or close while unconfirmed audio exists. The only other way out is Discard recording on the New meeting page, behind a dialog that names the recording and says no other copy exists. A discarded recording's half-made server row expires with its upload session.
- **Every 409 is one Conflict schema** with `reason` (`busy`, `not_uploading`, `missing_chunks`), `missing` and `retry_after`. Error, Recording, the create response and the chunk receipt allow no extra properties, so drift fails validation. Every `/api/v1` response in the e2e run, from the API specs and from the browser, is validated against the OpenAPI file with Ajv (dev only, MIT).
- **A chunk read takes at most 8 MiB + 1 bytes from a byte stream.** The session reads a request body with a BYOB reader, asking each time for no more than the room left plus one byte. A stream that is not a byte stream can only hand over whole pieces; then at most one piece more is pulled, and only 8 MiB + 1 is kept.
- **An empty Range header is handled if it arrives.** `keepEmptyRange` turns it into a malformed range at the Worker entry, so the route answers 416. Local workerd strips a header with an empty value before Worker code runs, so locally such a request arrives with no Range and gets the whole file; whether Cloudflare's edge does the same is not checked.

## 2026-10-22, v0.1 packet 4: transcription

- **One provider interface, `apps/web/lib/stt`.** `submit(job)` answers with the finished result or a pending handle, `fetch(handle)` serves async providers, `describe()` names the model and what it supports. Every provider maps to one shape: language, model, segments (start and end in ms, text, speaker number), speakers, optional words, and the provider's raw JSON in `transcripts.raw_json`. The provider comes from `settings.stt_provider`; its key is opened from the sealed column when the job runs and is never logged.
- **AssemblyAI: EU endpoint, upload, async job, webhook.** The audio goes from R2 to `api.eu.assemblyai.com/v2/upload` as a stream, never by a public URL. The job asks for `speech_models: ["universal-3-5-pro", "universal-2"]`, `speaker_labels`, `language_code` from Settings or `language_detection` for `auto`, and the keyterms. AssemblyAI calls `POST /api/v1/webhooks/assemblyai` with `X-Mtxt-Webhook-Secret`; the route is outside the session gate and stands on that secret. The webhook only wakes the job, which fetches the transcript itself, so the webhook body is never trusted for content.
- **Keyterms go to AssemblyAI as `keyterms_prompt`, not `word_boost`.** Checked 2026-10-22, and again 2026-10-23 for the model id, against AssemblyAI's model docs: async Universal-3.5 Pro (`universal-3-5-pro`; `universal-3-pro` was retired on 2026-09-02) supports 18 languages, Danish among them, and takes up to 1,000 keyterms of at most 6 words; Universal-2 takes 200. `word_boost` on Universal-3.5 Pro silently routes the job to Universal-2, and `keyterms_prompt` cannot be combined with `prompt` on async jobs. So Danish (and the other 17) sends up to 1,000 terms; `auto` and the other languages send at most 200, since detection may route to Universal-2. The response's `speech_model_used` is stored as the model.
- **A webhook secret per install, `settings.webhook_secret`, sealed.** Generated on the first request that finds none (and by the job, if it gets there first), with one conditional UPDATE so two first requests agree. A wrong or missing secret is 401. A transcript id the install does not know, or one already finished, is acknowledged with 200 and ignored, so a replay changes nothing. The same AssemblyAI transcript id never makes two rows: `transcripts` is unique on `(provider, provider_job_id)`.
- **`PUBLIC_URL` is a Worker var.** The queue consumer has no request to take a host from, and AssemblyAI needs the webhook's address. Like `INSTALL_ID`, it is set per deploy in `wrangler.jsonc`.
- **Workers AI Whisper behind a speech adapter in `packages/adapters`.** `apps/web` never touches the `AI` binding. Synchronous, one speaker ("Speaker 1"), keyterms as Whisper's initial prompt, through AI Gateway when `settings.ai_gateway_id` is set. The model page states no input limit (checked 2026-10-22); the file is base64-encoded in the Worker's memory, so the limit is 25 MiB, and a larger recording fails with "This recording is too long for Workers AI Whisper; switch provider in Settings" rather than being chunked.
- **`settings.ai_gateway_id` is a settings column and a field on the page,** in the Transcription section, optional. Packet 5's recap model uses it too. The `AI_GATEWAY_ID` var from packet 1 is now unused; packet 5 removes it.
- **Azure Speech, ElevenLabs Scribe, local Whisper and local Parakeet are not in v0.1.** They stay in the select so an admin sees what is coming, and saving one is refused with "Not available in this version". The data-flow panel names the two that work.
- **No provider means wait, not fail.** The data-flow panel already said "transcription waits until one is chosen". The job leaves such a recording `transcribing` with no transcript row, the page says it is waiting for a provider, and saving a provider in Settings queues every waiting recording.
- **The job.** Load the recording and the settings; take over the recording's one transcript row (pending) or write it; submit; store the job id or the result. The result is written in one D1 batch: the old segments of the row out, the new ones in (as JSON arrays through `json_each`, a few statements for 6,000 segments), the row `done`. Then the recap job goes out, then the status flips to `transcribed`; a crash between the two heals on the next delivery. A provider error marked retryable (network, 429, 5xx) and any unexpected error go back to the queue; the third delivery that fails marks the recording `failed`. Other errors fail it at once. The failure is a code in `recordings.failure` (`stt_failed`, `stt_too_long`, `stt_auth`, `stt_unavailable`, `stt_config`), shown in the reader's language, and the provider's own words in the new `recordings.failure_reason`. The provider's name is on the transcript row.
- **`transcripts.status`, `provider_job_id` and `is_comparison` are new columns; `speakers.speaker_index` too.** Migration 0004 only adds columns and swaps indexes. `status` is checked by the app, not by a CHECK, because adding a table constraint rebuilds the table and D1's rebuild cascades (packet 3). The one-transcript-per-recording index now covers non-comparison rows only.
- **Speakers are per meeting, by provider number.** A second recording of the same meeting reuses the row for speaker 0, 1, 2…, so a rename holds across recordings. New rows are labelled `Speaker n` and shown in the reader's language; a provider-given name is kept.
- **Rename and link set the whole value.** One server action takes the label and the linked user (or none), so a retry never doubles a change. Linking fills the name with the colleague's; unlinking keeps the name. Colleague search folds in JavaScript, since SQLite lower-cases ASCII only.
- **Keyterm highlighting is whole-word and Unicode-aware.** One regex per page with `\p{L}\p{N}\p{M}` boundaries, case-insensitive, longest term first, so "linje 2" is one mark and "Ærø" does not mark "Ærøskøbing".
- **The transcript renders in blocks of 100 segments.** Blocks far from the viewport are spacers with their measured (or estimated) height. The seeded 4-hour meeting of 6,000 segments keeps at most a few hundred rows in the page, opens in under half a second locally, and `?t=` lands on its segment.
- **The meeting page shares the player through a small store (`lib/playback.ts`).** The player and the transcript are separate client islands on a server page. A timestamp seeks the player and replaces `?t=` with `history.replaceState`.
- **The transcribing state looks again every 8 seconds** (`router.refresh`), so the transcript appears without a reload.
- **Local dev and the e2e run use `wrangler dev --local`.** The `AI` binding is remote-only, and without `--local` wrangler refuses to start in a non-interactive shell with no Cloudflare token. `next dev` starts with remote bindings off unless `MTXT_REMOTE_BINDINGS=1`.
- **Fake providers exist only in the e2e build.** A fake AssemblyAI (upload, submit, fetch, and a webhook posted back after a delay with a three-speaker Danish fixture) and a fake Workers AI are `route.e2e.ts` files, and their module throws in any other production bundle. The queue consumer is bundled by wrangler, not by Next.js, so it cannot see the build flag; it uses the fakes only with `AUTH_TEST_MODE=1` and a localhost URL in `ASSEMBLYAI_BASE_URL` or `WORKERS_AI_FAKE_URL`.

## 2026-10-23, v0.1 packet 8: recorder connection, the web side

- **The recorder connects through the browser, not with a device code against the identity provider.** The recorder never holds the IdP's credentials or a client secret, the web app stays the only OIDC client (one app registration per install, one place that checks tenant and domain), and a token is revoked per device from the library, without touching the IdP. The browser flow is PKCE-shaped: the recorder keeps the verifier and shows the browser only the challenge.
- **The token poll carries the challenge as well as the verifier.** With the verifier alone, a wrong verifier hashes to a challenge with no grant, which looks the same as "not approved yet" (202), and the recorder cannot tell. With both, a verifier that does not hash to the challenge is 410 at once, and a challenge with no grant yet is 202. The challenge is public (it is in the browser's address bar); only the verifier proves the poll comes from the recorder that opened the page.
- **A grant row exists only after Approve or Cancel.** A poll for a challenge with no grant reads one row and writes nothing, so a caller with no session can never write to the database. The one-per-second limit is kept on the grant row (`last_poll_at`, one conditional UPDATE); a challenge with no grant has nothing behind it to protect and is not limited. A poll that wins the grant inserts the token, writes `recorder_connected` and marks the grant redeemed in one D1 batch, each statement conditional on the grant still being approved, so two polls at once never make two tokens.
- **A used grant answers 410.** The server keeps only the token's hash, so it cannot answer the same token twice. A recorder that lost the 200 starts again; the token it never received shows in Recorders as never used, and the user can disconnect it.
- **20 pending grants per user is a condition inside the Approve insert.** The 21st Approve inserts nothing and the page says to wait or finish the open ones. Approve also deletes the user's grants that expired over a day ago, so the table stays small without a job.
- **The audit enum change rebuilds `audit_events`.** A CHECK constraint cannot be altered in SQLite. The rebuild is safe on D1 here because no table references `audit_events`, so the drop cascades into nothing; `check:d1-upgrade` counts the audit rows before and after.
- **The Recorders list loads when the dialog opens,** through a server action, not on every page render. It shows only working tokens (not revoked, not expired). Disconnect is optimistic and rolls back with a message when the server refuses (behaviour rule 2); it sets a value, so a retry revokes nothing twice.

## 2026-10-23, v0.2 packet 9: the desktop recorder for macOS

- **System audio through a Core Audio process tap, not ScreenCaptureKit.** `AudioHardwareCreateProcessTap` with a private, global stereo `CATapDescription` that leaves the recorder's own process out, read through a private aggregate device whose main sub-device is the default output, through the `objc2-core-audio` bindings. It needs only the audio recording permission, not Screen Recording, and gives the audio without a video stream to throw away. The cost is macOS 14.2 as the minimum (`LSMinimumSystemVersion`); a ScreenCaptureKit fallback for macOS 13 is not built. Without the permission a tap delivers silence, and opening one while macOS has not asked blocks on the prompt (measured: about 90 seconds in an unpermitted process), so the recorder explains and asks first, reads the state through TCC's own preflight call looked up at run time (there is no public query), and opens only the sources that are allowed.
- **One stereo Opus file in Ogg, microphone left, system audio right, 48 kbit/s.** The `opus` crate (libopus built from source) and the `ogg` crate's page writer, with the Ogg Opus headers written here (RFC 7845). About 86 MB for four hours, under the 2 GB the server takes. Pages are flushed every second and synced every five, so a crash leaves a file that plays to its last flushed second; the next start reads its duration from the last granule position and queues it. A recording with no audio on disk is forgotten; nothing with audio is.
- **The mixer runs on the wall clock, 200 ms behind.** Each source fills a lock-free ring from its audio thread (`rtrb`); the mixer resamples each to 48 kHz with a small windowed-sinc resampler, takes 20 ms frames, pads silence when a source is short and trims a source that runs more than 600 ms ahead back to 200 ms. Over hours the two device clocks drift; this keeps the channels within a fraction of a second without a drift estimator. Stop closes the file first and releases the devices on a side thread, because a Core Audio device can take seconds to let go.
- **The live transcript runs Parakeet through ONNX Runtime (`ort`) and Whisper through whisper.cpp (`whisper-rs`, with Metal).** Parakeet TDT 0.6B v3 int8 (670 MB) is the default: three graphs (log-mel preprocessor, encoder, decoder-joint) stepped greedily in Rust; 7.1 seconds of Danish speech took 0.42 s on an M-series Mac. ONNX Runtime has no prebuilt Intel macOS library, so the universal build has Parakeet in the Apple silicon slice only; an Intel Mac gets Whisper.

- **Language: the operating system's when a translation exists, otherwise the install's default.** As docs/spec.md says for the whole product; the packet text put the install's language first, and the spec wins.

## 2026-10-23, v0.1 packet 13: outbound webhooks with consent

- **Webhooks are a settings row, an event list and a consent per meeting.** The first consumer is a company's own case system, outside this repo. Up to five endpoints per install; "Send automatically" is `off`, `company` or `all shared` (stored `shared`), and never covers a private meeting. The owner's "Send to connected systems" sets `meetings.webhook_consent_at` and sends the current state at once. The action is named "Send to <label>" when every enabled endpoint that has a label has the same one, so an install that feeds one system says its name.
- **Setting a meeting to private takes the consent back.** Not in the packet text: without it, a meeting sent once by consent would keep flowing after its owner made it private, and its links would keep working, which reads as the opposite of "Private". The update rides in the visibility change's own batch. The owner gives consent again with the action.
- **A payload carries metadata and links, never content; it is built at each attempt.** The delivery row keeps the event and the meeting's metadata as queued (the delivery log's title, and `meeting.deleted`, whose meeting is gone), but each attempt builds the body afresh: current title, fresh one-hour links, and a cancel instead of a send when the meeting may no longer go. An unsent delivery of the same event to the same endpoint absorbs a new one, and a dedupe key (`transcribed:<transcript>`, `drafted:<version>`, `saved:<version>`, `deleted:<meeting>`) sends a transcript or a version once per endpoint, so a second press of the action, or the action after an automatic send, sends nothing twice. `recap.saved` waits a minute, so a typing session at the editor's 1.5-second autosave is one event.
- **The signature covers `<t>.<raw body>`, not the body alone.** The packet asked for HMAC-SHA256 over the raw body with `t=<unix>,v1=<hex>`; with the timestamp outside the MAC a captured request could be replayed with a fresh `t`. Inside it, a receiver that refuses a `t` older than 5 minutes stops replays. The README's snippet is the reference check.
- **Six attempts: the first, then 1 min, 10 min, 1 h, 6 h and 24 h.** The packet gave those five waits "then parked" and, elsewhere, "parks after the fifth failure"; read together, the fifth retry's failure (the sixth attempt) parks the delivery. Retry now sends a pending or parked delivery at once and keeps the count, so a parked one that fails again parks again. A Cloudflare queue delays a message at most 12 hours, so the 24-hour wait is two hops: a message that arrives before its delivery is due sends itself on.
- **One queue message is one attempt, claimed.** The message names its attempt number; a conditional UPDATE takes the delivery (pending at the previous attempt, or a `sending` whose 60-second lease lapsed), so a duplicate, a stale scheduled message after Retry now, or a redelivery never sends twice. An unexpected error after the claim gives it back, and the queue's redelivery retakes it at once; found by the e2e run, where a local D1 lock left a delivery in `sending` for its whole lease. Delivery is at least once: `X-Mtxt-Delivery` is the same on every attempt, for the receiver's dedupe. The nightly job removes finished deliveries over 30 days old and sends again any delivery whose message was lost.
- **No service identity, still.** A link is a grant, `v1.<meeting>.<format>.<expiry>.<endpoint>.<HMAC>`, under a key derived from `SETTINGS_KEY` for this one use (HMAC of a fixed label), checked with WebCrypto's constant-time verify, with no database row. At fetch time the meeting must still be one that may be sent and the endpoint must exist and be enabled; otherwise 404, the same as no meeting. An expired grant with a valid MAC is 410, which tells a receiver to ask again and tells nobody else anything. `audit_events.user_id` is NOT NULL, so `webhook_sent` and a webhook's `exported` name the meeting's owner, with the endpoint's label in `details`; the audit page shows "Markdown, fetched by Alex".
- **The transcript link answers JSON.** There was no transcript export before; a receiving system wants segments it can store, so the format is `language`, `speakers` (by the linked colleague's name, else the label) and `segments` with times, speaker and text. The recap links reuse the export button's Markdown and Word, now one builder (`lib/recap/export-file.ts`) for both routes.
- **Outbound requests go only to a public address.** An endpoint's URL is https, at most 2,048 characters, with no credentials and no local name (`localhost`, `*.internal`, `*.local`, a name without a dot); the host is resolved before every attempt and refused when any address is private: RFC 1918, loopback, link-local, carrier-grade NAT, unique local, multicast, unspecified, and IPv6 forms that carry such an IPv4 address. No redirect is followed (a 3xx is a failure), the answer's body is never read, and the request times out after 10 seconds. A Worker has no resolver of its own, so the adapters have a `HostResolver` and Cloudflare's is DNS over HTTPS (`cloudflare-dns.com`, JSON); a Docker edition binds the system resolver. The fetch resolves the name again, so a name that changes between the check and the request is not covered by the check; a Docker edition that needs that closed must connect to the checked address.
- **The e2e run's receiver is gated like the fakes.** `route.e2e.ts` at `/api/test/webhook-receiver`, a throw on import in any other production bundle, AUTH_TEST_MODE and localhost; the Worker lets `http://localhost:<port>` through the address check only in a bundle built with the `MTXT_E2E_BUILD` define and with AUTH_TEST_MODE=1, and the settings page only in the e2e build on localhost. `check:no-fakes` looks for the receiver too.
- **The delivery log is a page, `/settings/webhooks/{id}`,** so a link keeps the view (rule 5), under the admin gate the middleware already gives `/settings/`. It has no filter, so it has two empty states, none yet and a failed load. While a delivery is sending or due within 90 seconds it reads the server again every 3 seconds.
- **An endpoint's secret is made by the server and shown once,** in the answer to the add; it is sealed with its own context, `webhook_endpoints.secret`. Adding is a dialog, not an optimistic change, so the endpoint id is the server's. Enable, Disable and Delete are optimistic with rollback. Deleting an endpoint deletes its log; disabling it stops its links.
- **Migration 0009 adds and rebuilds once.** Two tables and two columns are added; `settings.webhook_auto_send` is checked by the app, since a CHECK would rebuild the settings table. `audit_events` is rebuilt for `webhook_sent` as 0007 did; `check:d1-upgrade` checks the audit rows survive and the new action is accepted.

## 2026-10-23, packet 13 after the Codex review

- **The address check is best effort on Cloudflare, and says so.** A Worker's `fetch` takes a hostname and resolves it again, and `connect()` cannot set the TLS server name apart from the address, so a connection cannot be pinned to the address the check saw; a fail-closed binding is not possible on this platform (lead's decision). Instead the host is resolved again immediately before every attempt, any private address in the answers refuses it, and an answer with a TTL under 60 s refuses it (`short_ttl`), so a name set up to flip between the check and the fetch has to hold a public answer for a minute. A Worker has no route into the customer's private network in any case. The Docker edition's HTTP client must connect to the checked address. The TTL a resolver reports is what is left of its cache, so a public host near the end of its cache time can be refused once; the next attempt, after the backoff, gets a fresh answer.
- **https on port 443 only.** The URL parser drops an explicit `:443`, so any port left is refused at the field and before every attempt. The add dialog says so.
- **`meeting.deleted` is a notice, not a snapshot.** It carries `meeting: { id, deleted_at }` and nothing else, and goes only to an endpoint that took an earlier event of the meeting and only while the meeting may still be sent at the delete. Before this, an endpoint that had taken an event got the delete with the meeting's title as it was at the delete, even after the owner had made it private and renamed it (Codex's sequence: send, make private, rename, delete). The title and the owner stay in the delivery row for the audit row and the delivery log, and never go out.
- **Delivered and `webhook_sent` land in one batch.** The audit insert selects from the delivery row it follows, so it is written only when the guarded update to `delivered` landed. A failed batch throws, the claim goes back, and the redelivered message sends again: at least once, with the same `X-Mtxt-Delivery`. The delete's audit row names the owner kept in the delivery row, with no meeting, like the delete's own row.
- **The export route is one exact shape.** The login gate's exemption and the Worker-entry guard both match `/api/v1/export/<one segment>`; anything deeper is 404, a method other than GET or HEAD is 405 and a request with a body is 400, all before OpenNext buffers a byte. A prefix exemption let `/export/x/y` past the gate and let a 1 MiB POST be buffered before its 405. The route takes the token as Next.js decoded it; decoding it again made `/export/%25` a 500.
- **`recap.saved` is debounced, not only delayed.** Each save moves the endpoint's unsent `recap.saved` delivery to a minute after itself, in one UPDATE that also takes the latest version's dedupe key, so a save at 59 seconds no longer lets the first save's delivery go at 60. The message queued by the first save comes early and sends itself on to the new due time.
- **`meeting.shared` means access widened.** It went out on every visibility change and on a removed reader, so a consumer heard "shared" when access shrank. Now only private to shared or company, shared to company, and an added reader send it; narrowing sends nothing, and Private still takes the consent back.
- **Six attempts, written the same everywhere.** The first attempt and five retries after the five waits, then parked; the spec's settings row, its Delivery bullet, `rules.ts`, the tests, the README and the delivery log's subheading all say six. The lead accepted six over the packet's "fifth failure".
